# testroms

Our own bare-metal test ROM sources. **Built ROMs are never committed** (AGENTS.md §3.1):
only sources live here; `testroms/build/` is git-ignored.

## Build

```bash
./scripts/build_testroms.sh          # needs Docker; writes testroms/build/*.nds and SHA256SUMS
```

The script runs `make -C testroms` inside the BlocksDS image pinned by digest in the script
itself. Local runs, `./scripts/verify.sh`, and CI all go through it.

## Layout

| Path | Purpose |
|---|---|
| `Makefile` | Builds every assembly ROM in `ROMS` and every libnds ROM in `CROMS` into `build/` and writes `build/SHA256SUMS`. |
| `smoke/` | Minimal ROM: ARM9 and ARM7 each spin in an infinite loop from their own entry point. No libnds, no BlocksDS crt0. |
| `boot/` | Direct-boot ROM: loads at `0x02000000` but enters at `0x02000100`, records r0-r14, CPSR and the IRQ/Supervisor stack pointers at `0x02000200`, then spins. Its addresses come from per-ROM variables in the `Makefile`. |
| `memmap/` | Memory-map ROM: exercises main RAM and its mirrors, both TCMs, VRAM bank A and an undefined I/O port from `0x02000100`, and records the values it read at `0x02004000` (slot layout at the top of `memmap/arm9.s`). It records observed values only; the expected ones are in `crates/runner/tests/memmap.rs`. |
| `vramdisp/` | VRAM-display ROM: writes POWCNT1 (display swap clear), VRAMCNT_A (MST 0) and DISPCNT (mode 2, block 0), then computes a test picture into bank A: colour bars, then red/green/blue/grey ramps, with bit 15 set on odd bar rows (layout at the top of `vramdisp/arm9.s`). Entered at `0x02000100`. No image asset. Expected pixels are in `crates/runner/tests/vramdisp.rs`. |
| `vrambanks/` | VRAM-banks ROM: all nine banks A-I in LCDC mode (markers at the first and last word of each window, the words just outside a lone bank, byte stores, off and on), then every MST and OFS that puts a bank in engine A or B BG or OBJ VRAM (47 table rows, each read at the window start, end and just outside), overlapping banks, banks in texture, extended-palette or undefined modes (CPU addresses empty), byte stores to each window, and a bank moving between mappings; then the ARM7's side (`arm7.s`), taking turns with the ARM9 through IPCSYNC: banks C and D as the ARM7's work RAM (VRAMSTAT, OFS 0 and 1, OFS.1 unused, overlap, byte stores, other modes and disabled banks), and the ARM9 reading what the ARM7 stored. Slot layout at the top of `vrambanks/arm9.s` and `arm7.s`; expected values in `crates/runner/tests/vrambanks.rs`. |
| `bgtext/` | Text-background ROM: writes POWCNT1 (engine A on the upper screen), VRAMCNT_A (MST 1, engine A BG VRAM), a computed palette, tile data and map cells, then BG0CNT-BG3CNT, scrolls and DISPCNT (display mode 1, BG mode 0, all four layers, character base 1) and shows four layers: BG0 (4 bits per pixel, 256x256, priority 0) with a tile in each flip combination and two palette numbers; BG1 (8 bits per pixel, 512x256, priority 1, scrolled 252 and 3); BG2 (4 bits per pixel, 256x512, priority 1, scrolled 250 vertically, a tie with BG1); BG3 (8 bits per pixel, 512x512, priority 2) whose horizontal scroll the ROM changes at line 101 by polling VCOUNT. Layout and data at the top of `bgtext/arm9.s`; entered at `0x02000100`. No image asset. The expected picture is worked out pixel by pixel from `docs/hw/bg-text.md` in `crates/runner/tests/bgtext.rs`, independent of `ninge-core`. |
| `bgengb/` | Engine B text-background ROM: writes POWCNT1 (engine B powered on, engine A on the upper screen), VRAMCNT_C (MST 4, engine B BG VRAM), a computed palette in engine B's half of the palette RAM, tile data and map cells, then engine B's BG0CNT-BG3CNT, scrolls and DISPCNT (display mode 1, BG mode 0, all four layers) and shows the same four-layer scene as `bgtext` on the lower screen, with engine A in display mode 0 (white) above. Layout and data at the top of `bgengb/arm9.s`; entered at `0x02000100`. No image asset. The expected picture is worked out pixel by pixel from `docs/hw/bg-modes.md` and `docs/hw/bg-text.md` in `crates/runner/tests/bgengb.rs`, independent of `ninge-core`. |
| `console/` | libnds console ROM (C; the only ROM with a C rule in the `Makefile`): `consoleInit` on engine A's BG0 (not `consoleDemoInit`, which uses engine B), three `printf` lines, then a line after five VBlank waits (the ARM9 VBlank IRQ is delivered) and a line after a FIFO round trip with the ARM7 (`getBatteryLevel`; the ARM7 is alive). It links [libnds](https://github.com/blocksds/libnds) (zlib licence) from the pinned BlocksDS image and uses BlocksDS's stock ARM7 core; both are used for the local and CI build only and are never committed or distributed with ninge. The Phase 3 DoD of #28. `crates/runner/tests/console.rs` reads the text back from the BG map: a cell's tile number is the character's ASCII code minus 32, which comes from the libnds font layout (the font starts at the space), so no font data is stored here. The glyphs are checked by eye. |
| `sched/` | Scheduler ROM: the ARM9 and the ARM7 each count forever in their own loop, storing the counter at `0x02001000` (ARM9) and `0x02002000` (ARM7) after every increment. The counters show how many instructions each CPU ran per frame (`docs/hw/scheduler.md`). Entered at its load address; expected values and the derivation are in `crates/runner/tests/scheduler.rs`. |
| `wramcnt/` | Shared-WRAM ROM: the ARM9 sets WRAMCNT to 0, 1, 2 and 3 in turn and writes a marker at `0x03000000` and `0x03004000`; the ARM7 reads what it sees at `0x03000000`, `0x03004000`, `0x037F8000` and `0x03800000`, reads WRAMSTAT, writes its own markers and reads them back. They hand over through a flag at `0x02003000` (no IPC yet). ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (slot layouts at the top of each `.s`). It records observed values only; the expected ones are in `crates/runner/tests/wramcnt.rs` (`docs/hw/wramcnt.md`). Entered at its load address. |
| `irq/` | Interrupt-controller ROM: each CPU reads IME, IE and IF at reset, writes all ones to them, probes byte and halfword writes to IE and IME and a write of ones to IF, and writes a pattern to its own IE; they hand over through a flag at `0x02003000` (no IPC yet) so each reads its IE again after the other has written its pattern. Nothing requests an interrupt and I stays set. ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (slot layouts at the top of each `.s`). It records observed values only; the expected ones are in `crates/runner/tests/irq.rs` (`docs/hw/interrupts.md`). Entered at its load address. |
| `disptime/` | Display-timing ROM: each CPU polls VCOUNT over one frame (264 values) and records its DISPSTAT and IF at chosen lines: the VBlank flag around lines 100, 192, 261, 262 and the wrap, the HBlank flag in line 50, the VCount-match flag with the setting 100, a write of FFFF to DISPSTAT, and IF latching of HBlank, VCount-match and VBlank with IME = 0 and clear-by-writing-1. The ARM9 also enables the ITCM, clears the high-vectors bit and takes the VCount and VBlank IRQs through a handler at `0x18`; the ARM7 checks IF only (its vector is BIOS, #27). The two CPUs run independently, no handshake. ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000`, the VCOUNT sequences at `0x02010000` and `0x02012000` (layouts at the top of each `.s`). Expected values are in `crates/runner/tests/display_timing.rs` (`docs/hw/display-timing.md`). |
| `ipc/` | IPC ROM: the two CPUs take turns through IPCSYNC itself (each step posts a nibble in IPCSYNC bits 8-11 and the next owner waits for it in bits 0-3; no RAM flag). They pin IPCSYNC's two nibbles and its IRQ (sent to a CPU that is not listening, then to one that is), the IPC FIFOs (send and receive order, the empty/full flags, the 17th send and the empty read with their error bit and its acknowledge, a flush by the sender, a disabled FIFO) and IF.17 and IF.18 (edge behavior and enable-on-condition). The ARM9 enables the ITCM, clears the high-vectors bit and takes IF.16, IF.17 and IF.18 through a handler at `0x18`; the ARM7 checks IF only (its vector is BIOS, #27). ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (layouts and the step table at the top of each `.s`). Expected values are in `crates/runner/tests/ipc.rs` (`docs/hw/ipc.md`). |
| `timers/` | Timers ROM: each CPU measures its own four timers against the frame (the edge into VCOUNT 192 starts and stops them): F/1024 and F/256 counts per frame, an F/1 timer feeding a count-up timer (8 overflows a frame), a stop that freezes the counter, a restart that loads the reload, a reload written while running, a 32-bit write of reload and start, IF latching only when the timer's IRQ enable is set, and timer 0's ignored count-up bit. The ARM9 enables the ITCM, clears the high-vectors bit and takes timer 3's IRQ through a handler at `0x18`; the ARM7 checks IF only (its vector is BIOS, #27). The two CPUs run independently, no handshake. ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (layouts at the top of each `.s`). Expected values are in `crates/runner/tests/timers.rs` (`docs/hw/timers.md`). |
| `dma/` | DMA ROM: each CPU drives its own four channels over small buffers of known words. The ARM9 covers Immediate 32-bit and 16-bit copies, destination increment, decrement and fixed, source decrement and fixed, aligned-down addresses, the busy (enable) bit, the fill register as a fixed source and a register as a destination, VBlank-start transfers (armed at line 100, read at lines 191 and 195), registers rewritten while armed, a cleared enable, a repeating channel with destination increment-and-reload over three VBlanks, two channels starting together, HBlank-start units counted over 50 lines and over a frame, IF bits 8 and 11 through a handler at `0x18` (the ROM enables the ITCM and clears the high-vectors bit), and a DTCM over main RAM that a transfer must not see. The ARM7 covers an Immediate copy polled to completion, the 14-bit count of channel 2, IF bits 8 + n only with the IRQ bit, a VBlank-start transfer, and no fill registers; it checks IF only (its vector is BIOS, #27). The two CPUs run independently, no handshake. ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (slot layouts at the top of each `.s`). Expected values are in `crates/runner/tests/dma.rs` (`docs/hw/dma.md`). |
| `swi/` | HLE BIOS ROM: each CPU takes three VBlank IRQs through the BIOS dispatcher (the user handler pointer at DTCM + `3FFCh` on the ARM9, `0380FFFCh` on the ARM7; the ARM9 uses the high vectors and a DTCM at `0x027C0000`) and makes an unimplemented SWI call from ARM and from Thumb state, then VBlankIntrWait (IME forced to 1, the caller's CPSR back, one more IRQ), SWI Halt with IME 1 and with IME 0, and the CPU's own halt (CP15 wait-for-interrupt on the ARM9, a HALTCNT write on the ARM7), each woken by the next V-blank, then the data SWIs (CpuSet and CpuFastSet in copy and fill modes, a count of 0 and the 8-word round-up; Div with each sign; Sqrt; GetCRC16; IsDebugger; LZ77 with byte and with halfword writes, the ARM9 also into VRAM bank A). The expected results are the model's (`docs/hw/hle-swi.md`): SWI `12h` is called without the `R3` callbacks the DS form takes, so on hardware it may differ. The results sit in memory at `0x02008000` (ARM9) and `0x02009000` (ARM7), laid out at the top of each `.s`. The handler raises V-blank in the IRQ check flags, records the CPSR and R0 it sees and clobbers r0-r3 and r12 so that only the dispatcher's save and restore keeps them; the ROM records the registers, SP_irq and the flags after the calls. The first test ROM that takes an ARM7 interrupt in the ROM rather than only latching IF. The two CPUs run independently, no handshake. ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (slot layouts at the top of each `.s`). Expected values are in `crates/runner/tests/swi.rs` (`docs/hw/hle-swi.md`). |
| `keypad/` | Keypad ROM: each CPU reads KEYINPUT (all ten key bits released), writes KEYCNT and reads back its defined bits, and writes the read-only KEYINPUT; the ARM7 also reads EXTKEYIN (nothing pressed, hinge open) and the ARM9 reads the address where it is absent. The expected values are the stub's (`docs/hw/keypad.md`). ARM9 observations are at `0x02004000`, ARM7 ones at `0x02005000` (slot layouts at the top of each `.s`); expected values are in `crates/runner/tests/keypad.rs`. |
| `divsqrt/` | Divider and square-root ROM (ARM9; the ARM7 spins): eleven divisions over every mode, sign combination and overflow (by zero, `-MAX / -1`, mode 3, garbage in the upper halves) and five square roots, each recording the busy bit right after the start and after the wait, the results and DIVCNT. The expected values are worked out in `crates/runner/tests/divsqrt.rs` from `docs/hw/divsqrt.md`. The record is at `0x02004000` (slot layout at the top of `arm9.s`). |

The header is built with a 0x4000-byte header size (`ndstool -h`), so the ARM9 offset meets the
range in `docs/hw/cart-header.md`. Line 1 of every source file is the SPDX line (`@ ...` in ARM assembly). Addresses come from
`docs/hw/cart-header.md` and `docs/hw/memory-map.md`.

## Running a ROM headlessly

`ninge-runner` loads a ROM, runs N frames, and prints one line with the frame count and an
FNV-1a 64 hash of each screen (the hash is defined in [`tests/golden/README.md`](../tests/golden/README.md)):

```bash
cargo run -p ninge-runner -- testroms/build/smoke.nds --frames 3
# frames=3 top=<016x> bottom=<016x>
```

Exit code 0 on success, 1 on an IO error (missing ROM), 2 on a usage error, 3 when the machine
refuses the ROM (an invalid header, `docs/hw/cart-header.md`). Tests find a
built ROM with `ninge_runner::testrom_path("smoke")`.
