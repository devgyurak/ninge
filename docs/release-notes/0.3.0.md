# ninge 0.3.0

The first release you can play: the keyboard, a gamepad and the mouse reach the console, and
cartridges are read and saved. Install with `cargo install ninge`, then run `ninge <rom>`.

## What works

- **Input.** The keyboard and a gamepad are the console's buttons, and the mouse is the touch
  pen: the left button presses the bottom screen. `Tab` turns on a keyboard cursor for the
  touch screen (`h` `j` `k` `l` move it, Space presses, `d` toggles a drag). `M`, held, is
  blowing into the microphone, and the grave accent key closes and opens the lid. The keys are
  in the README.
- **Cartridges.** The cartridge is read through its own protocol, so programs that load data
  from it run.
- **Saves.** The EEPROM, FLASH and FRAM save chips are emulated, and the save is kept in a file
  beside the ROM with the extension `.sav`. `--save PATH` names another file and
  `--save-type TYPE` names the chip when detecting it gets it wrong.
- **The real-time clock** follows the host's clock, and a program can set it.
- **The touch screen controller and the power management device**: a program can turn a
  backlight off, and can shut the console down, which ends `ninge`.
- **Synthetic firmware.** Programs read user settings and the touch calibration from a
  firmware image built by ninge. No firmware or BIOS dump is needed, and none is used.
- The keypad and lid interrupts.

## Changed

- **`q` and Esc no longer quit.** `q` is the L button now. Quit with `Ctrl-C` or `Ctrl-Q`.
- On Linux, building needs the libudev headers for the gamepad support: install `libudev-dev`
  and `pkg-config` (Debian and Ubuntu names) first.

## For hosts of `ninge-core`

- `Input` has two new fields, with `with_mic` and `with_wall_time` to set them: `mic`, and
  `wall_time`, the host's local time in seconds since 2000-01-01 00:00:00. The core reads no
  clock itself; a host that passes none gets a clock that starts at that moment and does not
  advance.
- New on `Machine`: `insert_save`, `save_data`, `save_type` and `save_generation` for the save
  chip (a host writes the save file when the generation changes); `is_shut_down`; and
  `backlight`, which says whether a screen is lit. The frame buffers are not dimmed for an
  unlit screen: that is the host's to draw.
- New in `cart`: `SaveType`, `SaveError`, `SaveChip` and `resolve_save`, which settles the chip
  type from the type a user asked for and the save file's size.
- The crate documentation now says which names a host is meant to build on and which are
  public but unstable before 1.0 (`debug`, `cpu`, `spi` and the detail types of `cart`).
- The savestate format changed (version 42). Before 1.0 a state from another version is
  refused, so savestates from 0.2.0 do not load.

## Known limitations

- **No sound.** The sound registers answer, so a program that waits on them goes on, but
  nothing is played.
- **No 3D.** Geometry commands are accepted and nothing is drawn, so a 3D scene is blank.
- **Speed is not tuned or measured yet.** Performance work is the last phase of the plan, so a
  program may not run at the console's speed.
- **Linux terminals are less tested than macOS.** CI builds and tests on Linux, but the
  shared-memory frame transfer has only been run by hand in Ghostty and kitty on macOS. On a
  terminal that refuses it ninge sends the frames compressed through the terminal instead.
- **One layout**: the two screens one above the other.
- **No debugger yet.**

These arrive in later releases; the roadmap is in `docs/PLAN.md`.
